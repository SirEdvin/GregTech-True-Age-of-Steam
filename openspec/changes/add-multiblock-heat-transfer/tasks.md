## 1. Heat model and controller API

Completion note: all implementation tasks are verified. Tasks 5.3 and 5.4 are
accepted with the user's explicit exceptions: datagen providers/cache writes
complete before the authorized timeout (exit 124), and unchanged pinned-dependency
Rhino/client-signature startup errors remain nonfatal. Neither is represented as
a clean run. Detailed evidence is in implementation-checkpoint.md.

The principal design decisions are settled. The controller owns countdown progression: other unloaded parts or hatches do not pause it, while controller unload/server shutdown preserve and pause its remaining time. Scheduled exchange precedes expiry for last-chance cooling. Dismantling a melting machine immediately destroys only its controller and own heat hatches with sound and no collateral effects. Lifecycle bookkeeping and transfer-balance/performance measurements belong to the implementation tasks below, not further product-design blockers. Implementation is in progress; unchecked tasks retain outstanding acceptance evidence described in implementation-checkpoint.md.

Tier revision: HV, EV, IV, and LuV use 2, 8, 32, and 128 J/(K * update), replacing the flat coefficient. Only the currently sending hatch determines the tier coefficient; the receiving tier does not throttle incoming heat. LuV-to-HV uses 128 and HV-to-LuV uses 2 J/(K * update), subject to unchanged donor-energy and equilibrium caps. Existing controller-pair deduplication remains in force.
